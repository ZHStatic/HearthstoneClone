## 三、核心架构

### 事件驱动的效果结算系统

```
                    ┌─────────────┐
                    │  GameEvent  │  ← 任何"发生的事"
                    │  (事件中心)  │
                    └──────┬──────┘
                           │ 广播事件
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ 卡牌效果  │ │ 关键词   │ │ UI 更新  │
        │ 监听器    │ │ 监听器   │ │ 监听器   │
        └──────────┘ └──────────┘ └──────────┘
```

**为什么用事件系统？** 炉石的效果是连锁触发的——一个亡语触发另一个亡语、法伤加成影响 AOE。如果用"直接调方法"，代码会散落在几十个文件里。事件系统让每个效果只管自己的监听，互不干扰。

### 目录结构

```
Assets/Scripts/
├── Core/                    # 纯逻辑，不依赖 Unity UI
│   ├── GameManager.cs       # 游戏总控（状态机）
│   ├── Card.cs              # 卡牌运行时实例
│   ├── CardData.cs          # ScriptableObject：卡牌模板数据
│   ├── Hero.cs              # 英雄（血量、护甲、英雄技能）
│   ├── Player.cs            # 玩家（手牌、牌库、法力水晶）
│   ├── Board.cs             # 战场（双方各 7 个随从位）
│   └── Minion.cs            # 随从运行时实例

├── Events/                  # 事件系统
│   ├── GameEventType.cs     # 枚举：所有事件类型
│   ├── GameEventBus.cs      # 事件总线
│   └── GameEvent.cs         # 事件数据结构

├── Effects/                 # 卡牌效果
│   ├── IEffect.cs           # 效果接口
│   ├── DamageEffect.cs      # 造成伤害
│   ├── SummonEffect.cs      # 召唤随从
│   ├── DrawCardEffect.cs    # 抽牌
│   ├── BuffEffect.cs        # 增减属性
│   ├── DestroyEffect.cs     # 消灭随从
│   └── HealEffect.cs        # 恢复生命

├── Keywords/                # 关键词
│   ├── Charge.cs            # 冲锋
│   ├── Taunt.cs             # 嘲讽
│   ├── Battlecry.cs         # 战吼
│   ├── Deathrattle.cs       # 亡语
│   └── DivineShield.cs      # 圣盾

├── AI/                      # AI 系统
│   ├── AIController.cs      # AI 入口
│   ├── ActionGenerator.cs   # 枚举所有合法操作
│   └── Evaluator.cs         # 局面评估函数

└── UI/                      # 界面
    ├── CardView.cs          # 单张卡牌 UI
    ├── HandView.cs          # 手牌区
    ├── BoardView.cs         # 战场视图
    └── GameHUD.cs           # 法力水晶、回合按钮等
```

## 四、各阶段详细说明

### 阶段 1：最小可玩原型（5-7 周）

> 色块当卡牌，白底黑字，点来点去，能分出输赢。

**功能清单：**
- [x] 卡牌数据结构（名称、费用、攻击力、血量）— ScriptableObject
- [x] 手牌区：从牌库抽牌，显示卡牌
- [x] 出牌：点击手牌，放到战场
- [x] 随从攻击：点己方随从 → 点目标 → 伤害结算 → 反击
- [x] 法力水晶：每回合 +1，上限 10
- [x] 回合流程：抽牌 → 行动 → 结束回合按钮
- [x] 胜负判定：英雄血量归零

**期间学会的 C#：**

| 功能 | 知识点 |
|------|--------|
| 卡牌数据结构 | `class`、属性、构造函数 |
| 手牌/牌库 | `List<T>`、随机数 |
| 出牌 | `Instantiate`、GameObject 生命周期 |
| 法力水晶 | `int` 变量、每回合更新 |
| 随从攻击 | 方法调用链、参数传递 |

**刻意不做：** 法术牌、英雄技能、关键词、动画、AI。

### 阶段 3：AI 对手（4-6 周）

**不搞深度学习。用博弈树搜索 + 评估函数。**

```
AI 决策流程：

1. 枚举所有合法操作
   ├── 能出的牌（费用够 + 目标合法）
   ├── 能攻击的随从（己方随从 → 敌方目标）
   ├── 英雄技能（费用够）
   └── 结束回合（永远可选）

2. 模拟每种选择的结果（深度 2-3 步）

3. 评估函数打分：
   ├── 场面优势 = 己方随从总属性 - 敌方随从总属性
   ├── 血量差
   ├── 卡差 = 手牌数量差
   └── 节奏 = 是否有效利用法力水晶

4. 选最高分 → 执行
```

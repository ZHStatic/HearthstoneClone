C# 高频知识点与面试表达

围绕本项目整理 C# 基础、工程写法和面试会被追问的点。重点不是背语法，而是能说清为什么这样写。

1. 类、对象、引用类型、构造函数

Microsoft Learn 对 class 的核心描述是：类是引用类型，用来定义对象的蓝图。变量保存的是对象引用，不是对象数据本身。

Card card = new Card(cardData);
Minion minion = new Minion(card.CardData, currentPlayer);

这两行的意思不是“复制一个模板文件”，而是在运行时创建新的对象实例。CardData 是模板，Card 是手牌/牌库里的实例，Minion 是场上的实例。

概念本项目例子面试怎么讲
类Player、Card、Minion类定义状态和行为，是代码里的模型。
对象new Player(...)对象是类在运行时创建出来的实例。
构造函数public Card(CardData data)创建对象时初始化必要字段。
引用类型Card card变量保存引用，多个变量可能指向同一个对象，所以状态修改要谨慎。

2. 字段、属性、访问控制和封装

字段 vs 属性

字段是类内部真正存数据的位置；属性提供读写入口。C# 属性从外面看像字段，但可以通过 get / set 控制访问。

public int CurrentHealth { get; private set; }

这表示外部可以读取血量，但只有类内部能修改血量。

面试表达：UI 不应该直接写 hero.CurrentHealth = 0。正确入口是 hero.TakeDamage(amount) 或 GameManager 规则方法，因为规则层需要记录日志、触发死亡和检查胜负。
为什么 Unity Inspector 字段常用 [SerializeField] private

public 代表所有代码都能访问和修改。[SerializeField] private 让 Unity Inspector 可以配置字段，同时保持代码层面的封装。

[SerializeField] private Text nameText;
[SerializeField] private Button button;

这就是本项目 UI View、Controller 和 GameManager 配置字段的常见写法。

3. 集合：List、IReadOnlyList、Dictionary、HashSet

类型特点本项目用途
List<T>有顺序、可增删、可按索引访问。手牌、牌库、战场随从、日志列表。
IReadOnlyList<T>只暴露数量和索引读取，不暴露 Add/Remove。Player.Hand、Board.GetMinions() 对外只读。
Dictionary<TKey,TValue>用 key 找 value。GameEventBus 用事件类型找到监听列表；BoardView 可记录 Minion 到 View 的映射。
HashSet<T>去重，快速判断是否出现过。CardData.CleanKeywords() 清理重复关键词。
为什么删除 List 元素时经常倒序遍历

正序遍历时删除元素会导致后面的元素索引前移，容易跳过元素。倒序删除时，已经检查过的后半部分即使索引变化也不影响后续检查。

for (int i = minions.Count - 1; i >= 0; i--)
{
    Minion minion = minions[i];
    if (minion.IsDead)
    {
        Board.RemoveMinion(minion);
    }
}

4. Action、delegate、event 和 GameEventBus

Action<T> 可以理解为“保存一个以后要调用的方法”。本项目的 View 常用它把点击事件交给上层。

private Action<Card> onClicked;

private void HandleClicked()
{
    onClicked?.Invoke(card);
}

CardView 不知道点击后是出牌、查看详情还是取消选择。它只把“这张 Card 被点了”通知出去。

C# event 和本项目 GameEventBus 的区别

event 是 C# 语言机制，限制外部只能订阅和取消订阅，不能随便触发事件。

GameEventBus 是本项目自己组织出的游戏事件中转站：用 Dictionary<GameEventType, List<Action<GameEvent>>> 管理监听器。

EventBus.Subscribe(GameEventType.MinionDied, ResolveDeathrattleOnMinionDied);
EventBus.Publish(new GameEvent(GameEventType.MinionDied, minion));

这样攻击、法术、战吼等不同来源造成死亡时，都能走同一个 MinionDied 入口触发亡语。

5. 项目高频写法

守卫语句

固定读法：如果失败情况成立，方法到此结束；否则继续往下走。

if (card == null) return GameActionResult.Failure(...);
if (!CurrentPlayer.HasCardInHand(card)) return GameActionResult.Failure(...);

// 能走到这里，说明前置条件已经通过。
enum 表达有限状态

CardType、KeywordType、GameActionType、GameActionFailureReason 都是 enum。它们适合表达“固定的一组选项”。

面试表达：用 enum 可以避免到处写魔法字符串，也方便 switch 和 Inspector 配置。

static class 工具类

KeywordTextFormatter 和 CardTextFormatter 是静态工具类。它们不需要保存对象状态，只负责把枚举和数据转换成 UI 文案。

partial class 的取舍

GameManager.BattleLog.cs 是 GameManager 的分部类文件。它让日志相关代码从主文件里分出去，但编译后仍然是同一个类。

面试要诚实讲：partial 只是文件组织手段，不是真正职责拆分。真正拆分应该是独立的 DamageResolver、EffectResolver 等系统。

string.Join 和字符串插值

多行文案先收集到 List<string>，再用 string.Join 组合，比在循环里反复 += 更清楚。

List<string> lines = new List<string>();
lines.Add("冲锋");
lines.Add("战吼：抽 1 张牌");
return string.Join("\n", lines);

6. 面试表达速记

Core / UI 分层

UI 不直接扣法力、删手牌、改血量。玩家点击后，UI 调用 GameManager 的规则入口，再读取 Core 状态刷新显示。

数据模板和运行时实例分离

CardData 是 ScriptableObject 模板，Card 是手牌/牌库实例，Minion 是场上实例。这样不会在运行时污染模板数据。

动作系统

GameAction 描述“想做什么”，GameActionGenerator 枚举“能做什么”，GameManager.ExecuteAction() 负责“真正怎么做”。玩家和 AI 复用同一套执行入口。

快照模拟

AI 不直接在真实局面上试错，而是复制 GameStateSnapshot，在快照上模拟动作并评分，最后只把选中的动作交给真实 GameManager 执行。

架构妥协

当前 GameManager 偏重，效果系统没有统一，快照模拟和真实规则有重复。这是项目复盘重点，不应该包装成商业级终版。

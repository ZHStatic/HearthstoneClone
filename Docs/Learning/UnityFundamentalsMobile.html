Unity 入门与本项目用法

只讲本项目真正用到的 Unity 基础。目标是能读懂场景、脚本、Inspector 绑定和运行时流程。

1. Unity 启动和脚本生命周期

Unity 脚本通常继承 MonoBehaviour。Unity 不是从你手写的 Main() 进入游戏，而是在场景加载、对象启用、每帧刷新、对象销毁等时间点自动调用特定方法。

场景加载 场景里的 GameObject 和组件被载入。
Awake 脚本实例加载时调用。通常做自身初始化。本项目 GameManager.Awake() 创建新对局。
OnEnable 对象和组件启用时调用。对象 inactive 时不会正常进入启用流程。
Start 第一次帧更新前调用，且晚于 Awake。本项目 GameUIController.Start() 绑定按钮并刷新 UI。
Update 每帧调用一次。本项目不是实时动作游戏，主要依赖按钮点击，所以几乎不用 Update。
OnDestroy / OnDisable 对象销毁或禁用时清理，例如 UI 按钮取消监听。
面试表达：本项目把对局初始化放在 GameManager.Awake()，因为 Awake 早于其他脚本的 Start。这样 UI 在 Start 里刷新时，Player、Enemy 和 Board 已经准备好。

2. GameObject、Component、Transform

GameObject 是场景里的对象容器；真正的功能来自挂在它身上的 Component。Unity 官方文档把 GameObject 描述为场景中的基础对象，本身不做太多事，功能由组件实现。

概念怎么理解本项目例子
GameObject场景里的对象容器。GameManager、Canvas、EndTurnButton
Component附加到 GameObject 上的功能模块。Button 负责点击，Text 负责文字，脚本组件负责逻辑。
Transform所有 GameObject 都有的位置、旋转、缩放组件。普通对象的空间信息。
RectTransformUI 对象使用的矩形布局组件。控制手牌区、战场区、按钮的位置、大小和锚点。
Hierarchy、Project、Inspector、Console 怎么分工

Hierarchy 看当前场景对象；Project 看 Assets 资源；Inspector 配组件字段和资源；Console 看错误、警告和日志。

本项目里，很多错误不是 C# 语法问题，而是 Inspector 引用没拖、Prefab 字段没绑定、ScriptableObject 数据里有空项。

3. 常用接口和方法

接口 / 方法准确含义本项目怎么用
MonoBehaviourUnity 脚本组件的基类，Unity 会调用它的生命周期方法。GameManager、GameUIController、CardView 等 UI/场景脚本继承它。
GetComponent<T>()获取同一个 GameObject 上的某种组件。MinionView.Awake() 没绑定 Button 时尝试自动获取。
Instantiate(original, parent)运行时克隆对象；克隆 GameObject 或 Component 时会连同子对象和组件一起克隆。HandView 创建 CardView，BoardView 创建 MinionView。
Destroy(obj)移除 GameObject、Component 或资源对象。早期刷新 UI 会销毁重建；阶段 4.6 后改为轻量复用，减少频繁 Destroy。
SetActive(false)禁用 GameObject，让它不显示且不参与启用状态。手牌或战场 View 多余时隐藏，而不是销毁。
AudioSource.PlayOneShot播放一次 AudioClip，不会取消同一 AudioSource 上已经播放的 OneShot。BattlePresentationController 播放出牌、攻击、伤害、圣盾和结算音效。

4. Prefab、ScriptableObject、Inspector 绑定

Prefab

Prefab 是可重复使用的 GameObject 模板。官方文档把 Prefab 定位为可保存 GameObject、组件和属性的资源模板。本项目的 CardViewPrefab 和 MinionViewPrefab 用来批量生成手牌和战场 UI。

ScriptableObject

ScriptableObject 是 Unity 的数据资源类型，适合保存可复用的静态配置。本项目用 CardData 保存卡牌模板，用 DeckData 保存预制套牌。

正确做法：运行时变化放到 Card 和 Minion。不要在对局中直接改 CardData，否则模板资源会被污染。

[SerializeField] private

Unity 官方文档说明，[SerializeField] 可以强制 Unity 序列化 private 字段，让它显示在 Inspector 中。它适合“Inspector 能配置，但其他代码不能随便访问”的字段。

[SerializeField] private HandView handView;
[SerializeField] private CardView cardViewPrefab;
.meta 文件协作规则

Unity 用 .meta 保存资源 GUID。Prefab、Scene、ScriptableObject、图片、音频等资源引用依赖 GUID。默认不要手动创建或修改这些文件。

本项目协作规则：Codex 新增 C# 脚本只创建 .cs；回到 Unity 后由 Unity 自动导入并生成 .meta。

5. UGUI：Canvas、Button、Text、Layout

UGUI 的所有 UI 元素都应放在 Canvas 下。Unity UI 文档说明，Canvas 是 UI 元素所在区域，UI 元素必须是 Canvas 的子对象。Canvas 还会使用 EventSystem 帮助消息系统处理交互。

概念用途本项目例子
CanvasUI 根区域，控制 UI 渲染模式和层级。战斗界面、套牌选择和结算面板都在 Canvas 下。
EventSystem处理 UI 点击、选择和事件分发。没有它，Button 通常无法正常响应点击。
Button用户点击并释放时触发 OnClick。结束回合、英雄、英雄技能、套牌选项。
Text / Image显示文字和背景、高亮颜色。血量、法力、反馈、随从状态、目标高亮。
Layout Group自动排列子 UI。手牌和战场随从横向排列。
Anchor决定 UI 跟随父物体或屏幕的哪一侧缩放。手牌贴底、战场居中、按钮靠右。

6. 本项目 Unity 映射

GameManager.Awake()开局创建 Player、Enemy、Board，进入第一回合。
GameUIController.Start()绑定按钮点击事件，执行首次刷新。
DeckSelectionController处理套牌选择、演示模式、结算面板切换。
HandView / BoardView用 Prefab 创建或复用 UI View，刷新显示，不判断规则。
CardData / DeckDataScriptableObject 数据资源，保存卡牌模板和套牌模板。
BattlePresentationController根据 Core 结算日志播放音效和目标脉冲，不参与规则结算。
面试表达：静态布局、字号、颜色、边距优先放在 Editor 和 Prefab；运行时状态、规则判断、按钮状态和反馈文本由代码控制。

7. 常见错误排查

NullReferenceException

含义：代码想使用一个对象，但这个对象是 null。

本项目真实例子：牌库列表里有空的 CardData，new Card(data) 后访问 data.Cost 报错。后来在 Player 创建牌库时跳过空项。

按钮没反应

检查场景有没有 EventSystem；检查 Button 是否 interactable；检查 GameUIController.Start() 是否绑定了监听；检查 Inspector 字段是否拖对。

Prefab 字段丢失

检查 Prefab 上脚本是否 Missing；检查 Text、Button、Image 字段是否绑定；检查是否手动移动 Unity 资源导致 GUID 引用异常。

运行时状态写进 ScriptableObject

如果对局中直接修改 CardData，会把模板当成实例用。正确做法是：模板数据在 CardData，运行时费用在 Card，场上生命和攻击权限在 Minion。

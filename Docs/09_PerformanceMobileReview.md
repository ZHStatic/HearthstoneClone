# Stage 4.8 Performance And Mobile Review

最后更新：2026-07-08

本文记录阶段 4.8 的第一轮移动端 / 性能意识巡检。它不是商业上线级优化方案，而是为了让当前求职 Demo 能清楚说明：哪些性能问题已经处理，哪些暂时保留，后续什么时候再升级。

## 当前结论

- `HandView` 和 `BoardView` 已经从全量 `Destroy` / `Instantiate` 改成轻量复用。
- 当前没有必要引入完整对象池；手牌和场上随从数量很小，完整对象池会增加学习和维护成本。
- 当前没有发现忽略实际规则结果、误导性 UI 反馈、重复 formatter 或 Core/UI 反向依赖候选。
- Unity Game 视图已检查 `1920 x 1080` 和 `2340 x 1080`，当前布局表现良好，不需要调整 Scene / Prefab。
- 阶段 4.8 当前可以收口：已有轻量复用和横屏比例适配足够支撑求职 Demo 演示。

## 已完成的性能相关处理

| 区域 | 当前做法 | 价值 |
|------|----------|------|
| 手牌 UI | `HandView` 复用已有 `CardView`，不够时才创建，多余时隐藏 | 避免每次抽牌、出牌都重建整只手牌 |
| 战场 UI | `BoardView` 复用已有 `MinionView`，并维护随从到 View 的映射 | 减少对象创建，也让受击脉冲目标更稳定 |
| 表现反馈 | `BattlePresentationController` 只播放短音效和轻量缩放协程 | 表现层不改规则，不阻塞 Core 结算 |
| 文本 formatter | `KeywordTextFormatter` / `CardTextFormatter` 统一文案 | 避免多个 View 重复拼装同类文本 |
| 套牌选择 | `DeckOptionView` 负责单个选项，`DeckSelectionController` 负责流程 | 避免单个控制器继续堆大量 UI 细节 |

## 热路径观察

战斗中最频繁发生的是：

```text
玩家点击
-> GameManager 结算
-> GameUIController.RefreshAll()
-> HandView.Refresh()
-> BoardView.Refresh()
-> HUD 文本刷新
```

当前风险判断：

- `RefreshAll()` 仍然是整屏刷新，这是阶段性简化，不是成熟项目最终做法。
- 因为手牌最多约 10 张、双方随从最多各 7 个，当前整屏刷新可接受。
- 当前主要收益已经来自 View 复用，而不是继续拆成大量局部刷新事件。
- 后续如果加入更复杂动画、伤害数字、敌方手牌隐藏、日志面板或移动端真机测试，再考虑局部刷新或 UI 状态机。

## 本轮不做的优化

| 不做 | 原因 | 以后什么时候做 |
|------|------|----------------|
| 完整对象池框架 | 当前对象数量小，轻量复用已经解决主要问题 | 卡牌飞行动画、死亡前动画或大量临时特效出现后 |
| 事件驱动 UI 局部刷新 | 当前手动 `RefreshAll()` 更直观，便于学习和调试 | UI 子系统明显增多，刷新成本或状态错乱变成真实问题后 |
| 深入 GC Profiler 调优 | 还没有真机性能数据，过早微优化价值低 | 做移动端构建并用 Profiler 看到具体 Alloc 热点后 |
| Scene / Prefab 自动改布局 | Unity 资源容易破坏引用，布局应在 Editor 中调整 | 用户确认并在 Unity Editor 中配合检查时 |

## 移动端适配检查结果

已在 Unity Editor 的 Game 视图中检查：

| 分辨率 | 用途 | 结果 |
|--------|------|------|
| `1920 x 1080` | 16:9 横屏基准 | 布局表现良好，不需要修改 |
| `2340 x 1080` | 19.5:9 手机横屏近似 | 布局表现良好，不需要修改 |

检查结论：

- 手牌、双方战场、英雄血量、法力和反馈文本没有明显重叠。
- 选中攻击、法术或英雄技能后的目标高亮能正常观察。
- 当前不需要新增响应式布局代码。
- 当前不需要改 Scene、Prefab 或 ScriptableObject。

## 面试表达

可以这样讲：

```text
这个 Demo 没有为了性能直接上完整 UI 框架或对象池。
我先处理了最明显的问题：手牌和战场刷新不再每次 Destroy / Instantiate，而是复用已有 View。
当前卡牌数量很小，所以整屏 RefreshAll 仍然保留，换来代码更直观、调试更容易。
如果后续做移动端真机或加入复杂动画，我会先用 Profiler 找到真实 GC Alloc 和 UGUI rebuild 热点，再决定是否拆局部刷新、对象池或表现队列。
```
